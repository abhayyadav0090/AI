# NexOS — Backend API Reference

Base URL: `http://localhost:3000` (dev) · `https://yourdomain.com` (prod)

All responses use `Content-Type: application/json`.

## Conventions

- **Requires login:** routes marked this way read the `token` cookie (set by `POST /api/auth/google`). Without a valid cookie they answer `401`.
- **Errors** look like `{ "error": "<message safe to show the user>", "code": "..." }`. Some simple validation errors have no `code`.
- **Origin check:** a request whose `Origin` is neither the app's own host nor listed in `ALLOWED_ORIGINS` gets `403` with `code: "ORIGIN_NOT_ALLOWED"`. Unknown `/api/*` paths get `404` with `code: "NOT_FOUND"`.
- **Body size:** 2 MB for every route except `POST /api/chat`, which accepts up to 9 MB, and `POST /api/study/docs`, which accepts up to 6 MB (both only after login and rate limits) because they carry files.
- **Rate limits:** 600 requests per 15 minutes per IP on `/api`; `POST /api/chat` and `POST /api/complete` also share per-user limits of 30 per minute and 500 per day. Counters are kept in server memory.

## `GET /api/health`

Returns server health. No login needed.

**Response 200:**
```json
{ "status": "ok", "db": "connected", "timestamp": "2026-11-10T10:30:00.000Z", "version": "4.1.3" }
```
`db` is `connected` or `idle`; `version` is the `version` in `package.json`.

## `GET /api/config`

Public settings for the sign-in button: `{ "googleClientId": "..." }` (an empty string when `GOOGLE_CLIENT_ID` is not set).

## `POST /api/auth/google`

Signs in with the credential returned by Google Sign-In.

**Request body:** `{ "credential": "<Google ID token>" }`

**Response 200:** `{ "name", "email", "picture" }`, and sets the `token` cookie (JWT, 7 days, `httpOnly`, `SameSite=Lax`, `Secure` in production or on HTTPS).

| Status | Meaning |
|---|---|
| 400 | `credential` is missing |
| 401 | Google login failed, or the Google email is not verified |
| 500 | `code: "AUTH_CONFIG"`: `JWT_SECRET` is not set |

## `POST /api/auth/logout`

Clears the cookie: `{ "ok": true }`.

## `GET /api/me`

Requires login. Returns `{ "_id", "name", "email", "picture" }`.

## `GET /api/bootstrap`

Returns the authenticated user's public identity and current workspace state in one request. This is used by the Classic and Enterprise startup flows to avoid serial `/api/me` and `/api/state` requests.

**Response 200:**
```json
{
  "user": { "_id": "...", "name": "...", "email": "...", "picture": "..." },
  "state": null,
  "workspaceUpdatedAt": null
}
```
`state` is the saved workspace object or `null` for a new account. `workspaceUpdatedAt` is the server's authoritative update timestamp for that workspace, or `null` when no workspace exists. Requires the existing httpOnly login cookie. The endpoint does not modify or migrate workspace data.

## `GET /api/state` and `PUT /api/state`

Read or replace the authenticated user's workspace object. `GET` returns `{ "state": object | null, "updatedAt": timestamp | null }`; `PUT` accepts `{ "state": object }` and returns `{ "ok": true, "updatedAt": timestamp }`. The timestamps are generated by MongoDB/Mongoose and can be used to reconcile a confirmed local cache. Existing clients can ignore these additional fields; `GET /api/bootstrap` remains the combined startup endpoint.

## `POST /api/chat`

Sends one message to NexAI (Gemini). The server saves your message and the reply, so chats survive refreshes. Requires login. Nothing is saved if the AI call fails.

**Limits:** 30 requests/minute and 500/day per signed-in user. A message can be up to 4000 characters, a chat holds up to 200 messages, and each user keeps up to 100 chats (oldest are removed).

**Request body:**
```json
{
  "chatId": "66f0c0ffee...",
  "message": "Help me prioritize my tasks",
  "system": "You are NexAI ... (the user's task context)",
  "attachments": [{ "name": "assignment.pdf", "data": "<base64>" }]
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `chatId` | `string` | no | Omit to start a new chat |
| `message` | `string` | yes, unless `attachments` is sent | Max 4000 characters. With attachments and no text, the server asks the model to analyse the files. |
| `system` | `string` | no | Context for the model, max 6000 characters |
| `attachments` | `array` | no | Up to 3 files, 6 MB in total after decoding (see below) |

**Attachments:** each item is `{ "name": string, "data": base64 string }`. The server checks the real content of every file, not its name or reported type. Accepted: PDF, PNG, JPEG and WEBP (by their file signature) and text or code files (`txt`, `md`, `csv`, `json`, `xml`, `html`, `css`, `js`, `ts`, `py`, `java`, `c`, `cpp`, `h`, `cs`, `go`, `rs`, `php`, `rb`, `sql`, `yml`, `yaml`, `log`, `tex`) with no binary bytes. Text from a file is cut at 60,000 characters. Files are sent to the model with that one message and are not stored; the saved chat keeps your message and the file names. With attachments the model call waits up to 80 seconds and is tried once.

The model receives the most recent 24 saved messages of a chat as context. When the message looks like a question about earlier messages or a follow-up to one (for example "what did we discuss", "what was my first message"), the server looks back through the whole saved chat, within a size limit, and tells the model how much of the chat it can see.

**Streaming:** send `"stream": true` and the reply arrives as server-sent events (`Content-Type: text/event-stream`) instead of the JSON below: `delta` events carry `{ "text": "..." }`, a final `done` event carries `{ "chatId", "title", "updatedAt" }`, and an `error` event carries `{ "error", "code" }`. If the stream stalls after text was already sent, the text received so far is kept and saved with a short note that it was cut off. Without `stream` the server answers with the JSON below.

**Response 200:**
```json
{ "text": "Here are your priorities...", "chatId": "66f0c0ffee...", "title": "Help me prioritize my tasks", "updatedAt": "2026-10-16T10:30:00.000Z" }
```

**Errors** always look like `{ "error": "<message safe to show the user>", "code": "..." }`:
| Status | `code` | Meaning |
|---|---|---|
| 400 | `BAD_REQUEST`, `TOO_LONG`, `CHAT_FULL` | Invalid message, too long, or the chat is full |
| 400, 413, 415 | `BAD_ATTACHMENT` | Invalid attachments, more than 3 files, more than 6 MB in total (413), or an unsupported file (415) |
| 404 | `NOT_FOUND` | Chat does not exist |
| 429 | `RATE_LIMIT`, `DAILY_LIMIT` | Too many messages |
| 500 | `AI_CONFIG`, `SERVER_ERROR` | API key or server problem |
| 502 / 503 | `AI_ERROR`, `AI_BUSY` | Gemini failed or is over its quota (a stalled first attempt is retried, then the fallback model is tried; with attachments the call is tried once) |

## `GET /api/chats`

Lists the signed-in user's chats, newest first: `{ "chats": [{ "id", "title", "updatedAt" }] }`.

## `GET /api/chats/:id`

Returns one chat with all messages: `{ "chat": { "id", "title", "updatedAt", "messages": [{ "role", "content", "ts" }] } }`.

## `DELETE /api/chats/:id`

Deletes one chat: `{ "ok": true }`.

## `PUT /api/me`

Changes the signed-in user's display name. Body: `{ "name": "..." }` (1 to 60 characters, extra spaces are removed). Returns `{ "name", "email", "picture" }`. A name chosen here is kept when the user signs in again.

## `DELETE /api/me`

Deletes the signed-in user's NexOS data: workspace data, NexAI chats, study documents and sections, and push settings. The shared Google identity record is kept (other independently deployed apps may use it), but every device is signed out so none can write the deleted data back. Body must be `{ "confirm": "DELETE" }`, otherwise the server answers 400. Returns `{ "ok": true }` and clears the login cookie.

## Push reminders

Browser push for task reminders. Routes marked login need the cookie; `GET /api/push/config` does not.

### `GET /api/push/config`
`{ "enabled": true | false, "publicKey": "<VAPID public key>" | "" }`. `enabled` is `false` until the `VAPID_*` variables are set.

### `GET /api/push/preferences` and `PUT /api/push/preferences`
Requires login. `GET` returns `{ "reminderTime": "09:00", "enabled": true, "timeZone": "Asia/Kolkata" }`. `PUT` accepts any of `reminderTime` (24-hour `HH:MM`), `enabled` (boolean) and `timeZone` (an IANA name), at least one of them, and returns `{ "ok": true, "reminderTime", "enabled", "timeZone" }`. Invalid values get `400`.

### `POST /api/push/subscribe` and `DELETE /api/push/subscribe`
Requires login. `POST` body: `{ "subscription": { "endpoint": "https://...", "keys": { "p256dh": "...", "auth": "..." } } }`, answering `{ "ok": true }`. The endpoint must be `https` on a known push service, and the keys must be valid, otherwise `400`. Without `VAPID_*` the server answers `503` with `code: "PUSH_NOT_CONFIGURED"`. `DELETE` body: `{ "endpoint": "https://..." }`, answering `{ "ok": true }`.

### `POST /api/push/test`
Requires login. Sends a test notification to the user's subscriptions: `{ "ok": true, "delivered": 1 }`. `404` when the user has no subscription, `503` with `PUSH_NOT_CONFIGURED`, and `502` when the push service rejects it.

## `POST /api/complete`

Single-shot prompt completion. Simpler than `/api/chat`.

**Limits:** shares the `/api/chat` limits (per signed-in user). Not saved.

**Request body:**
```json
{
  "prompt": "Give me a one-line description for this task: 'Deep work session'",
  "system": "You are a helpful assistant. Be concise."
}
```

**Response 200:**
```json
{
  "text": "Uninterrupted 90-minute focus block for high-priority work."
}
```

## Study Studio

Upload notes, then ask NexAI to tutor you from them. All routes require login and every query is filtered by the user id from the cookie, never by anything in the request body. Only the extracted text sections are stored (the original file is not kept). Study routes use the normal `{ "error", "code" }` error shape.

### `GET /api/study/docs`

Lists the user's documents, newest first.

**Response 200:**
```json
{
  "docs": [
    { "id": "665f...", "title": "Biology ch 2", "subject": "Biology", "fileName": "ch2.pdf", "kind": "pdf",
      "size": 482113, "pages": 12, "chunkCount": 31, "truncated": false, "createdAt": "2026-11-24T10:30:00.000Z" }
  ],
  "usage": { "docs": 1, "chunks": 31, "maxDocs": 20, "maxChunks": 1500, "maxFileMB": 4 }
}
```

### `POST /api/study/docs`

Uploads one document and reads it inside the request (no background queue). **Limits:** 6 MB JSON body, the file itself up to 4 MB, PDFs up to 300 pages, 12 uploads per hour per user, one file read at a time on the server. The body parser runs only after login and the upload limit.

**Request body:**
```json
{ "name": "ch2.pdf", "data": "<base64 of the file>", "title": "Biology ch 2", "subject": "Biology" }
```
`title` and `subject` are optional (the title defaults to the file name). The type is decided from the real bytes: a text PDF (starts with `%PDF-`), or a `.txt`, `.md` or `.markdown` file in UTF-8.

**Response 201:** `{ "doc": { ...same fields as in the list } }`

**Errors:** `400 BAD_DOCUMENT` (missing, empty or unreadable data), `413 BAD_DOCUMENT` (file too large, or a PDF over 300 pages), `415 BAD_DOCUMENT` (unsupported type), `422 BAD_DOCUMENT` (password-protected or damaged PDF, no readable text such as a scanned PDF, or reading took too long), `409 DOC_DUPLICATE` (the same file was uploaded before), `403 STUDY_QUOTA` (20 documents or 1,500 sections reached), `503 STUDY_BUSY` (another file is being read; try again), `429 RATE_LIMIT`.

### `DELETE /api/study/docs/:id`

Deletes the sections first, then the document. Returns `{ "ok": true }`, or `404 NOT_FOUND` when the id is not one of the user's documents.

### `POST /api/study/ask`

Asks the tutor a question about the user's material. **Limits:** shares the per-user AI limits (30 per minute, 500 per day) with `/api/chat`.

**Request body:**
```json
{ "question": "How do plants make food?", "docId": "665f...", "history": [ { "role": "user", "content": "..." }, { "role": "assistant", "content": "..." } ] }
```
`docId` is optional and limits the search to one document (`404 NOT_FOUND` if it is not the user's). `history` is optional: up to the last 6 turns are used for follow-up questions. The question is 2 to 600 characters.

The server finds the best matching sections with a MongoDB text index (words from the question; no embeddings) and sends up to 6 of them to Gemini with an instruction to answer only from them. When nothing matches, no Gemini call is made.

**Response 200 (found):**
```json
{ "found": true, "answer": "Plants make food by photosynthesis ... [1]",
  "sources": [ { "n": 1, "title": "Biology ch 2", "page": 4, "heading": "", "section": 7, "snippet": "Photosynthesis takes place in the chloroplasts..." } ] }
```
`sources` lists the sections the answer cites (all retrieved sections if it cites none). `page` is `null` for TXT and Markdown files.

**Response 200 (not found):** `{ "found": false, "answer": "I couldn't find that in your study material. ...", "sources": [] }`. This is also returned when the model reports that the sections do not contain the answer.

**Errors:** `400 BAD_REQUEST`, `404 NOT_FOUND`, and the usual AI errors (`503 AI_BUSY`, `502 AI_ERROR`, `429 RATE_LIMIT`, `429 DAILY_LIMIT`).

## Frontend ↔ Backend Integration

When running with the backend, `app.js` calls `/api/chat` and `/api/complete` instead of hitting Gemini directly. The API key is never exposed to the browser.

There is no standalone mode. All AI calls go through the backend, which calls Google Gemini with `GEMINI_API_KEY`.



## Changes in 2.2.0

- Requests whose `Origin` is neither the app's own host nor listed in `ALLOWED_ORIGINS` get `403` with `code: "ORIGIN_NOT_ALLOWED"`.

- `DELETE /api/me` also signs out every device (cookies issued before deletion are rejected).


## Changes in 3.0.0

- Workspace reads now return lean MongoDB results and select only the stored data field.
- Versioned static assets can be cached immutably; application HTML is briefly cached with stale-while-revalidate.

## Changes in 3.3.0
- `POST /api/chat` accepts `attachments` (up to 3 files, 6 MB in total) and uses a 9 MB body limit for that route only. Other routes keep the 2 MB limit.
- New error code `BAD_ATTACHMENT` (400, 413, 415).

## Changes in 3.4.1 to 3.4.5
- `POST /api/chat` accepts `"stream": true` and then answers with server-sent events (3.4.1); without it the JSON response is unchanged.

- Questions about earlier messages make the server look back through the whole saved chat, and the model is told how much of the chat it sees (3.4.3, 3.4.4).
- A stream that stalls after text arrived keeps that text, saved with a short "cut off" note, instead of failing (3.4.5).
